## 14. 换工作区怎么办（已用 Junction 解决）

### 背景

DSH 只从 `<工作区根>/.dsh/skills` 加载技能，路径写死在代码里，改不了配置。
所以工作区一变，技能就加载不到。

### 已做的处理（2026-10-26）

用 **Junction（目录联接）** 在两个候选工作区都挂上了同一个技能库，**不占额外空间**：

| 工作区位置 | Junction 状态 |
|---|---|
| `C:\Users\33846\OneDrive\文档\deepseek-harness\default-workspace\.dsh\skills` | ✅ 原始位置（143 个技能） |
| `E:\毕业设计\project\.dsh\skills` | ✅ Junction → 原始位置 |
| `E:\毕业设计\.dsh\skills` | ✅ Junction → 原始位置 |

**验证结果**：三处都能读到 143 个技能，`project-rules` 及其 2 个附录均可读。

### 关键特性

- **零额外空间**：Junction 是目录链接，不复制文件（节省 22 MB × 2）
- **自动同步**：任何一处修改，三处同步生效；以后新增技能只需装到原始位置
- **Git 安全**：`.gitignore` 已加 `.dsh/`，不会污染仓库

### 创建命令（如需在其他位置再加）

```powershell
$src = 'C:\Users\33846\OneDrive\文档\deepseek-harness\default-workspace\.dsh\skills'
$tgt = '<新工作区>\.dsh\skills'

# 先建父目录
New-Item -ItemType Directory -Path (Split-Path $tgt -Parent) -Force

# 建 junction
New-Item -ItemType Junction -Path $tgt -Target $src

# 验证
(Get-ChildItem $tgt -Directory).Count   # 应返回 143
```

### 切工作区前的检查

在 DSH 里换工作区后，先确认：

```powershell
# 1. 当前工作区是否有 .dsh/skills
Test-Path '.\.dsh\skills'

# 2. 能否读到技能
(Get-ChildItem '.\.dsh\skills' -Directory).Count
```

如果返回 0 或路径不存在，按上面的命令补建 junction。

### ⚠️ 注意事项

1. **Junction 指向 OneDrive 目录**：如果 OneDrive 同步异常或目录被移走，junction 会失效
2. **不要在 junction 目录里直接改技能**：虽然可行（改的是同一份文件），
   但容易搞混；建议统一改原始位置 `/default-workspace/.dsh/skills/project-rules`
3. **删除 junction 不会删原文件**：`Remove-Item <junction>` 只删链接，
   但 `Remove-Item -Recurse -Force` 作用于 junction 时需格外小心

### 如果 Junction 不可用（降级方案）

某些环境不允许建 junction，此时只能复制（占 22 MB）：

```powershell
Copy-Item 'C:\...\.dsh\skills' '<新工作区>\.dsh\skills' -Recurse
```

缺点是**不会自动同步**，改了技能要手动重复制。
