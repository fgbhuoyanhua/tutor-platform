# 订单状态机台账

> 本文是订单状态流转的唯一权威说明。代码实现在 `backend/.../domain/OrderDomain.java`，单元测试在 `backend/src/test/.../domain/OrderDomainTest.java`。
> 改动状态机时，请同时更新本文、单元测试、双端常量与前端按钮条件（见文末清单）。

## 一、六个状态

| 值 | 常量名 | 中文 | 是否占用时段 |
| --- | --- | --- | --- |
| 0 | `PENDING` | 待确认 | 是 |
| 1 | `CONFIRMED` | 已预约 | 是 |
| 2 | `TEACHING` | 授课中 | 是 |
| 3 | `FINISHED` | 已完成 | 否 |
| 4 | `CANCELED` | 已取消 | 否 |
| 5 | `REJECTED` | 已拒绝 | 否 |

“是否占用时段”直接对应数据库生成列 `active_flag`：仅当状态为 0/1/2 时该列取 1，其余取 NULL。唯一索引 `uk_slot_active(tutor_id, appoint_date, time_slot, active_flag)` 依靠它实现“占用中的时段不可重复预约、作废后自动释放”。

## 二、五个动作与操作方

| 动作 | 中文 | 允许的操作方 | 要求的前置状态 |
| --- | --- | --- | --- |
| `confirm` | 接单 | 老师（`OP_TUTOR`） | 待确认 0 |
| `reject` | 拒绝预约 | 老师（`OP_TUTOR`） | 待确认 0 |
| `cancel` | 取消预约 | 学生（`OP_STUDENT`） | 待确认 0 |
| `start` | 开始授课 | 老师（`OP_TUTOR`） | 已预约 1 |
| `finish` | 确认完成 | 学生（`OP_STUDENT`） | 授课中 2 |

操作方不符抛 403；前置状态不符抛业务异常；未知动作直接拒绝。

## 三、转移矩阵

行是当前状态，列是动作，单元格写目标状态；“拒”表示校验不通过。

| 当前 \ 动作 | confirm | reject | cancel | start | finish |
| --- | --- | --- | --- | --- | --- |
| 待确认 0 | → 已预约 1 | → 已拒绝 5 | → 已取消 4 | 拒 | 拒 |
| 已预约 1 | 拒 | 拒 | 拒 | → 授课中 2 | 拒 |
| 授课中 2 | 拒 | 拒 | 拒 | 拒 | → 已完成 3 |
| 已完成 3 | 拒 | 拒 | 拒 | 拒 | 拒 |
| 已取消 4 | 拒 | 拒 | 拒 | 拒 | 拒 |
| 已拒绝 5 | 拒 | 拒 | 拒 | 拒 | 拒 |

## 四、五条合法转移（可对外表述为“五条”）

| 序号 | 转移 | 动作 | 操作方 |
| --- | --- | --- | --- |
| 1 | 0 待确认 → 1 已预约 | confirm | 老师 |
| 2 | 1 已预约 → 2 授课中 | start | 老师 |
| 3 | 2 授课中 → 3 已完成 | finish | 学生 |
| 4 | 0 待确认 → 4 已取消 | cancel | 学生 |
| 5 | 0 待确认 → 5 已拒绝 | reject | 老师 |

其中 1→2→3 构成主干链路（三个阶段），4、5 是待确认阶段的两条终止分支。

## 五、为什么校验放在服务端

`OrderDomain.next(current, operator, action)` 是纯函数，不依赖 Spring，可直接单测。Service 层在改状态之前调用它，拿到目标状态才写库。

前端按钮条件只是体验层：即使前端被绕过、或用接口直接调用，服务端仍会因前置状态或操作方不符而拒绝。这解释了“未开始授课就确认完成”这类请求为什么会被拦住。

## 六、与调课的关系

调课不改变订单状态。学生提交调课申请写入 `reschedule` 表（0 待同意 / 1 已同意 / 2 已拒绝），教师同意后才修改 `appointment` 的日期与时段，订单状态仍停留在“已预约”。因此调课与状态机是两条并行的规则，不要混为一谈。

调课前置条件：订单必须是 `CONFIRMED`，且同一订单同时只能存在一条待处理申请。

## 七、测试覆盖对照

`OrderDomainTest` 现有用例与矩阵的对应关系：

| 用例 | 覆盖内容 |
| --- | --- |
| `legalFlow` | 转移 1、2、3（主干链路） |
| `rejectFlow` | 转移 5 |
| `cancelFlow` | 转移 4 |
| `forbiddenOperators` | 四次越权：学生接单、学生开始授课、老师取消、老师确认完成 |
| `illegalTransitions` | 五次乱序：跳过授课直接完成、重复接单、未接单开始、已取消后开始、已拒绝后完成 |
| `unknownAction` | 未知动作 `pay` 被拒 |
| `statusText` | 六态文案与未知值的兜底文案 |

## 八、改动状态机时必须同步的地方

1. `backend/.../domain/OrderDomain.java` —— 状态常量、`next()` 分支、`statusText()`

6. 前端按钮条件：`web-app/src/views/order/OrderList.vue`、`mobile-app/pages/order/list.uvue`
