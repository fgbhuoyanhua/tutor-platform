1. **`request.uts` 里不要 `data as Map<string, any>`**
   传 `UTSJSONObject` 时运行时抛 `UTSJSONObject cannot be cast to io.dcloud.uts.Map`。

2. **`uni.showToast` 默认只显示 1.5 秒**

### 移动端 ADB 坐标必须精确

- 预览图尺寸 ≠ 设备像素，换算比例按 `wm size`
- **UVUE 里文字节点常是 `clickable=False`，父容器才绑事件，uiautomator 抓不到**

```python

d = u2.connect("127.0.0.1:16384")
xml = d.dump_hierarchy()   # 用正则找 bounds 算中心
```

## 十一、移动端滚动问题排查记录（2026-10-26）

### 现象

「收入统计」页内容超出屏幕，但**无法滚动**。用户描述「能滑但松手又弹回」。
日志与截图证据：`scroll-view` 渲染为 `android.widget.ScrollView`，
`scrollable=false`，内容最大 y2 = 1920 而容器 y2 = 1770（超出 150px）。

### 已排除的方案（7 种全失败）

| # | 尝试 | 结果 |
|---|---|---|
| 1 | 移除 `.page { flex: 1 }` | ❌ 无关 |
| 2 | `style="height: 1000px"`（与能滚动的订单页一致） | ❌ |
| 3 | `style="height: 1400px"` | ❌ |
| 4 | `style="height: 1787px"` | ❌ |
| 5 | 高度写进 CSS 类 `.page { height: ... }` | ❌ 更差（完全不生效） |
| 6 | `direction="vertical"`（uni-app x 官方新属性，替代 `scroll-y`） | ❌ |
| 7 | 移除 `scroll-view` 自身的 `padding`（改由内层 view 承担） | ❌ |

### 关键对照实验

| 页面 | `.page` 样式 | ScrollView 渲染 | scrollable |
|---|---|---|---|
| 订单列表 | 仅 `background` | y=133-1770, h=1637 | **true** ✅ |
| 我的 | 仅 `background`+padding | y=133-1770, h=1637 | false（但内容本就一屏，正常） |
| 收入统计 | 仅 `background`+padding | y=133-1770, h=1637 | **false** ❌ |

**ScrollView 标签、尺寸、样式几乎完全一致，但 scrollable 不同** —— 说明差异在页面内容结构里，
目前未定位到具体元素。

### 参考资料

- [uni-app x scroll-view 官方文档](https://doc.dcloud.net.cn/uni-app-x/component/scroll-view.html)：
  属性表里**没有 `scroll-x`/`scroll-y`**，用 `direction`（默认 `vertical`）
- [uniappx scroll-view 不能滚动问题](https://blog.csdn.net/czdbgsy/article/details/140869085)：
  提到「需要实体高度」，但本地实测无效
