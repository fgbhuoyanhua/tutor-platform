### 二、本轮新增的三项功能（代码已完成，测试见第四节）

#### 1. 老师信用分 + 等级 + 推荐排序显式化

- **业务口径**：信用分 0~100，初始 100；违规一次按管理员填的分数扣（默认 10，最大 50）；完成一单 +1（`GovernanceServiceImpl.onOrderFinished`，目前**没有接到订单完成动作上**，留了口子）
- **等级阈值**（前后端一致）：`>=90 A 金牌老师`、`>=75 B 优质老师`、`>=60 C 普通老师`、`<60 D 受限老师`。低于 60 视为受限（`CreditRules.isBookable` 已提供，**订单创建处还没拦**，见待办）
- **推荐分公式**（`CreditRules.recommendScore`）：
  `认证 35%（已认证=1 / 待审=0.35 / 未认证=0）+ 评分 25%（rating/5）+ 完课 20%（log10(完课数+1)/2 封顶1） + 信用 20%（credit/100）`
  权重在 `application.yml` 的 `app.recommend.*` 可调（`RecommendConfig` 注入成 `CreditRules` Bean）
- **推荐理由**由 `CreditRules.reasonLabel` 生成，如「已认证教师 · 完课 12 单 · 好评 4.8 · 信用 95」
- **接口**：`GET /api/tutors/recommend-ranked?subjectId=&limit=`（公开）、`GET /api/tutors/recommend-weights`（公开）
  旧接口 `GET /api/tutors/recommend` **保留不动**（订单/其它地方还在用，接口契约没改）
- **前台**：Web 卡片加等级 tag + 详情抽屉加信用分进度条 + 推荐弹窗显示权重公式/推荐分/推荐理由；小程序卡片加「A 金牌老师」tag + 已认证院校行，首页「智能推荐」改调 recommend-ranked

#### 2. 投诉举报 + 管理端治理闭环

- **学生**（`/api/complaints`，需学生角色）提交：被投诉老师、类型 1爽约/2私改价格/3骚扰辱骂/4虚假信息/5其他、说明（≤500字）、可选关联订单
  - 不能投诉自己；关联订单必须是自己的且老师匹配；**同一人对同一老师同一订单同时只能一条待处理**（`uk_complaint_pending` 唯一索引 + 先查 409 兜底，与资格认证同一套思路）
- **管理员**（`/api/admin/complaints`）列表 + 处理：`PUT /api/admin/complaints/{id}/handle?accept=&deduct=&note=`
  - 成立 → 写一条 `tutor_violation`（type=1）+ 扣信用分 + 累加 `tutor.violation_count`
  - 驳回 → 必须填 note；已处理过的再处理返回 400（幂等）
  - 双方各发一条系统站内信（type=3）
- **前台**：Web 学生端 `/student/complaints`（我的投诉 / 提交投诉 两个 tab）、管理端 `/admin/complaints`（待处理/已成立/已驳回/全部）；小程序 `pages/student/complaint`

#### 3. 课时账单 + CSV 导出

- `GET /api/tutor/bill?month=yyyy-MM`（老师）返回 `{month, finishedCount, finishedMinutes, totalAmount, pendingCount, items[]}`
  - **金额/单价一律取 `appointment` 快照字段**，老师之后改价不影响历史账单（已实测：改成 999 元后账单仍是 120.00）
  - 时长按时段推算（`GovernanceServiceImpl.slotMinutes`，08:00-10:00 → 120 分钟，解析失败兜底 120）
  - 学生姓名脱敏（`张**`）
- `GET /api/tutor/bill/export?month=yyyy-MM` 返回 **UTF-8 带 BOM** 的 CSV，Excel 直接打开不乱码
- **前台**：Web 老师端 `/tutor/bill`（月份选择、4 个汇总卡、明细表、导出按钮）；小程序 `pages/tutor/bill`（上月/下月切换、汇总、明细）

### 一、业务口径（写论文和答辩都按这个，别再改）

- 认证状态字段 `tutor.cert_status`：`0 未认证 / 1 审核中 / 2 已认证 / 3 已驳回`
- 老师提交时填：就读院校、专业、年级、证明类型、证明编号（学信网报告才必填）、证明材料文件、补充说明
- 同一老师**同时只能有一条待审申请**，由数据库唯一索引保证，不是靠代码查重兜底
- 管理员通过 → 把申请里的院校/专业/年级回写进 `tutor` 表、`tutor.cert_status` 置 2、记 `cert_time`，申请记录 `status` 置 1；驳回 → 申请记录 `status` 置 2 + 写 `review_note`，`tutor` 字段不动、`tutor.cert_status` 置 3
- 审核结论会给老师发一条站内消息（`send(0L, tutorId, 3, ...)`，类型 3 是系统通知）
- **已认证老师可以再次提交**（用于院校专业变更），提交后状态回到 1「审核中」，前台暂时不显示已认证，等审核通过再恢复。如果希望已认证锁死不让改，改 `submit` 里的一条判断即可
- 前台展示口径：列表卡片带「已认证」标签 + 一行金色院校专业；老师自己的「我的家教信息」页顶部有认证卡片（未认证 / 审核中 / 已认证 / 驳回四种形态）

### 六、这轮踩过的坑（照抄，别重走）

| 坑 | 症状 | 正解 |
|---|---|---|
| **`/api` 双前缀** | 前端拿到的 `certUrl` 本来就是 `/api/tutor-cert/file/...`，再拼 baseURL 变 `/api/api/...` → 404 | `getBlob` 里对以 `/api` 开头的路径先 `slice(4)` 去掉前缀；接口测试脚本也踩过一次，一开始 4 条 FAIL 全是这个 |
| **blob 响应被拦截器当成数据** | 下载材料时 `api.code` 取不到，直接抛错 | 拦截器里加 `if (response.config.responseType === 'blob') return response` |

| **唯一索引报错不能只靠查重** | 并发两条同时通过查重，都去 INSERT → `DuplicateKeyException` 500 | 先查待审返回 409，再 `catch DuplicateKeyException` 兜底转 409 |
| **上传目录会进 Git** | `.gitignore` 没写 `uploads/`，`git status` 里出现运行时文件 | 已写进 `.git/info/exclude`（本地忽略，不改用户的 .gitignore） |
| **读上传文件的路径安全** | 直接拼文件名可穿越目录 | 文件名正则 `^[a-zA-Z0-9]{8,64}\.(jpg|jpeg|png|pdf)$` + `normalize()` 后校验 `startsWith(目标目录)` |
| **`el-upload` 自定义上传** | 默认上传行为不符合鉴权要求 | 用 `http-request` 自定义，走共享包 `postForm`，带 token |
| **Web 构建临时目录** | `vite build` 报 `Access denied`（esbuild 删临时文件） | 先设 `$env:TEMP=$env:TMP=<项目外临时目录>` 再 build |

### ⭐ 根因只有一行：根 `scroll-view` 必须加 `flex: 1`

```vue

```

**缺 `flex: 1` 时**：UVUE 不按父容器算它的可用高度，而是把滚动内容层按**视口高度铺满**
→ `scrollable=false`，内容超出也滚不动，看起来极像框架 bug。

**已应用范围：16 个页面全部统一**（`auth/login`、`auth/register`、`favorite/list`、`home/index`、

`message/chat.uvue` 是页内局部滚动，不适用。

### 实测对照

| 写法 | scrollable | 能滚 |
|---|---|---|
| `height: 1000px`（原样） | ❌ false | ❌ |
| **`flex: 1; height: 1000px`** | ✅ **true** | ✅ |
| 仅 `flex: 1`（去 height） | ✅ true | ✅ 但丢失「调高度微调留白」能力 |
| `flex: 1; height: 1px` | ✅ true | ✅（CSDN 写法，等效）|
| 仅 `height: 1px` | ✅ true | ❌ 容器压成 3px，页面几乎空白 |

## 十一、移动端滚动问题排查记录（2026-10-26，已解决 ✅）

> ⚠️ 本节原记录「7 种方案全失败、疑为框架问题」的结论**已被推翻**，
> 下面保留历史 + 给出**真正的根因与解药**。

### 真正的根因

根 `scroll-view` **缺 `flex: 1`**。

UVUE 在没有 `flex: 1` 时不按父容器计算 `scroll-view` 的可用高度，
而是把滚动内容层**按视口高度铺满** → `scrollable=false`，内容超出也滚不动。
表现极像「框架把内容层高度钳制了」，所以之前 9～13 种 CSS 试法全部无效——
**它们全都缺了 `flex: 1` 这个前提**。

### 解药（一行）

```vue
<scroll-view class="page" scroll-y="true" style="flex: 1; height: 1000px;">
```

### 实测对照

| 写法 | scrollable | 能滚 |
|---|---|---|
| `height: 1000px`（原样，缺 flex） | ❌ false | ❌ |
| **`flex: 1; height: 1000px`** | ✅ **true** | ✅ |
| 仅 `flex: 1` | ✅ true | ✅（但丢失「调高度微调留白」能力）|
| `flex: 1; height: 1px` | ✅ true | ✅（CSDN 帖写法，等效）|
| 仅 `height: 1px` | ✅ true | ❌ 容器压成 3px，页面几乎空白 |

### 已应用

16 个页面统一改为 `style="flex: 1; height: <原值>px;"`。
`message/chat.uvue` 是页内局部滚动，不适用。

### 历史：曾经失败过的方案（现在知道为什么失败了）

| # | 尝试 | 结果 | 现在的原因 |
|---|---|---|---|
| 1 | 移除 `.page { flex: 1 }` | ❌ | 方向反了——需要的是**加上** flex:1 |
| 2 | `height: 1000px` | ❌ | 缺 flex:1 |
| 3 | `height: 1400px` | ❌ | 缺 flex:1 |
| 4 | `height: 1787px` | ❌ | 缺 flex:1 |
| 5 | 高度写进 CSS 类 | ❌ | 缺 flex:1 |
| 6 | `direction="vertical"` | ❌ | 缺 flex:1 |
| 7 | 移除 `scroll-view` 自身 padding | ❌ | 缺 flex:1（但 padding 坑本身是真的）|

| 9 | `flex-direction: column` | ❌ | 缺 flex:1 |
| 10 | 换 `.page-nopad` 类 | ❌ | 缺 flex:1 |
| 11 | 换 `list-view` | ❌ | 只接受 `list-item` 子节点，整页空白 |
